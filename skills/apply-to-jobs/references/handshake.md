# Handshake

Use `https://app.joinhandshake.com` in the signed-in browser. Read the actual posting rather than relying on a match badge or profile recommendations. Use the current search UI, requested role/location filters, and newest-first sorting unless the user chooses another order. Search one role family at a time and paginate before changing queries.

Read employer, requisition/title, location, employment type, deadline, requirements, and eligibility language. Apply the configured workspace's fit rules. The application log normalizes Handshake posting IDs from `/job-search/<id>`, `/jobs/<id>`, and `/public/jobs/<id>`; still distinguish separate requisitions or locations with similar titles.

For a hosted application, inspect the job-detail Apply control and its modal. Upload this application's resume as a new document and check the actual selected attachment and populated fields. Follow the saved submission preference.

For external apply, keep useful search/form tabs, confirm the employer and opening on the HTTPS destination, and link the ATS URL to the existing record. If redirected to a generic careers page, locate the exact title and location; mark a removed/unavailable posting with an explanatory status instead of submitting to a different opening. Follow [accounts and verification](accounts.md) for signup or email verification.

A visible submission confirmation or corresponding portal state is needed before marking `applied`. Keep resumable forms open at `review_ready`; close job tabs after confirmed completion or when there is nothing useful to resume. Do not change the user's Handshake profile, interests, recommendations, saved searches, inbox, or unrelated account settings while applying. Do not upload a resume to optimization/recommendation services as part of an application.
